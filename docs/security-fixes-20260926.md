# 2026-09-26 安全审计修复说明

## 修复内容

- 注册：使用 D1 原子批处理，合法邀请码验证、用户插入和邀请码核销在同一事务内完成；异常自动回滚。重复、失效邀请码不创建有效账户。
- 代理身份：Workers 默认仅读取 `CF-Connecting-IP`；Docker 只读取可信代理设置的 `X-Real-IP`。禁止在多个可伪造请求头之间回退，Docker 默认端口仅绑定宿主机回环地址。
- 限流：使用带上限条件及 `RETURNING` 的单条 D1 UPSERT，解决并发覆盖；按窗口隔离，定期删除过期计数。
- 同步缓存：使用内部命名缓存，缓存副本设置有效期；无论命中与否，对客户端始终返回 `private, no-store`。缓存故障不会阻断同步。
- 静态安全头：通过 `webapp/public/_headers` 覆盖静态页面，禁止内联脚本和页面嵌入；HTML meta 策略同步收紧。
- 依赖：升级 `fflate` 到 0.8.3、`@simplewebauthn/server` 到 13.3.3，并同步锁文件。
- 类型：改用 Vite 支持的布尔 `treeshake` 配置，并适配 fflate 新版字节数组类型。
- 测试：改用能返回正确退出状态的 Python unittest，补齐邀请注册前置流程，真实执行跨用户权限、附件上传/单次下载令牌、刷新和同步隔离测试。Node 测试使用一次性 Miniflare D1/R2/Cache 验证并发、故障回滚及缓存命中。
- 发布：Docker 构建推送依赖安全工作流成功，工作流包括类型检查、回归、生产依赖审计和前端构建。

## 验证命令

需要 Node.js 22 或更新兼容版本，以及 Python 3；测试使用一次性本地数据，不连接生产数据库。

```sh
npm ci
npm run typecheck
npm run test:security
npm audit --omit=dev --registry=https://registry.npmjs.org
```

Python 不在默认 PATH 时，可通过 `PYTHON` 环境变量指定可执行文件。`scripts/test_security.py` 单独运行要求全新的测试实例，不能对生产实例运行；正常情况下请使用 `npm run test:security`，由测试启动和清理隔离环境。

## 上线前检查

1. 备份数据库、附件和持久化密钥，先在测试环境演练恢复和升级。
2. 检查代理拓扑。此次 Docker 端口收紧会停止远程直接访问 8787，需要 HTTPS 反代；容器化代理应使用私有网络。
3. 新增 `rate_limit_budgets` 表由运行时版本化初始化补建，也提供幂等 `0002` 迁移；不删除已有业务数据。
4. 限流从缓存计数改为 D1 写入，增加数据库请求及写入量，换取跨并发请求的严格预算。检查 D1 配额与延迟；高流量实例可另行迁移到 Durable Object 原子计数，不应回退到缓存读改写。
5. 检查 HTML、静态页面和 API 的实际响应头，以及 Passkey、PWA 离线使用和通知连接。首次升级后让浏览器获取新页面与 Service Worker。
6. 使用通过安全工作流的固定镜像版本或摘要发布。

## 范围

本次修复不修改 Bitwarden 加密协议，不重置既有用户凭据。已知 ZIP 解析公告通过升级处理；面向超大压缩包的解压配额和可终止后台解压属于后续资源治理工作，不应将升级理解为所有解压拒绝服务风险已消除。
